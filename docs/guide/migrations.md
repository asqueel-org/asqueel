# Project and migrate a physical schema

Query execution and schema migration are separate operations. Genro SQL builds
a physical description; `genro-sqlmigration` compares that description with a
database and prepares migration commands.

Install the migration and PostgreSQL dependencies when you need this path:

```sh
pip install 'genro-sql[postgresql,migration]'
```

## Resolve names before producing migration data

For a model returned by `resolve_model()` or `inspect_postgres()`, use
`to_physical_builder()` before rendering:

```python
from genro_sql import SqlMigrationRenderer, to_physical_builder


def desired_structure(model):
    physical = to_physical_builder(model)
    return SqlMigrationRenderer(physical).render()
```

This applies the same physical schema, table prefix, explicit table name and
column names used by the query compiler. Rendering the original logical recipe
directly does not perform this resolved-name mapping.

The result is normalized migration data, not SQL. It contains physical columns,
keys, supported constraints and indexes. UI metadata, formula columns, identities
used by the application and row policies are excluded from physical DDL. Retain
the original application model alongside this projection.

`SqlRenderer` is not a DDL generator in the current package. Use the migration
pipeline rather than expecting `builder.renderer_sql` to create tables.

## Prepare commands for an existing database

The function below inspects only the physical schemas selected by the model
and returns the migrator and its prepared command text:

```python
from psycopg.conninfo import conninfo_to_dict
from genro_sql import SqlMigrationRenderer, to_physical_builder
from genro_sqlmigration import PgDatabase, SqlMigrator


def prepare_migration(dsn, model):
    physical = to_physical_builder(model)
    desired = SqlMigrationRenderer(physical).render()
    schemas = sorted({table.physical_schema for table in model.tables.values()})
    if not schemas:
        raise ValueError('Choose a nonempty application schema to migrate')
    database = PgDatabase(
        conninfo_to_dict(dsn),
        application_schemas=schemas,
    )
    migrator = SqlMigrator(
        database,
        ignore_constraint_name=True,
        removeDisabled=True,
    )
    migrator.ormStructure = desired
    migrator.prepareMigrationCommands()
    return migrator, migrator.getChanges()
```

Include an explicit `dbname` in the DSN; `PgDatabase` requires it. The migrator's
application-schema list must be the schemas you intend to manage. A schema
shared with unrelated application objects needs a deliberate ownership strategy.

`removeDisabled=True` suppresses removal events; it does not guarantee that all
other changes are harmless or reversible. Inspect the returned commands for the
actual change you intend. To apply the prepared commands, call
`migrator.applyChanges()` explicitly. After applying, prepare a fresh migration
from the same desired model and check that `getChanges()` is empty. Do not infer
idempotence merely from successful execution.

## Project an imported model

Imported primary, unique and foreign-key constraint names may differ from the
names generated by the current projection. The default behavior rejects that
loss of naming fidelity. To compare structural equivalence while ignoring
constraint-name differences, opt in at both boundaries:

```python
from genro_sql import SqlMigrationRenderer, to_physical_builder
from genro_sqlmigration import SqlMigrator


def prepare_imported_structure(database, imported_model):
    physical = to_physical_builder(
        imported_model,
        allow_constraint_rename=True,
    )
    migrator = SqlMigrator(
        database,
        ignore_constraint_name=True,
        removeDisabled=True,
    )
    migrator.ormStructure = SqlMigrationRenderer(physical).render()
    migrator.prepareMigrationCommands()
    return migrator
```

Here `database` is a `PgDatabase` configured for the intended physical schemas.
`allow_constraint_rename=True` does not issue a rename command and does not
remove other validation. Original names remain in imported metadata. If names
must be reproduced exactly, this projection is not suitable for that import.

## Handle rejected projections

`to_physical_builder()` raises `UnsupportedFeatureError` when it cannot safely
represent the supplied model. In particular:

- Any `model.warnings` blocks projection, including unmanaged objects or a
  requested schema that was not found. There is no general ignore-warnings flag.
- Imported identity/generated columns, sequence ownership or sequence-dependent
  defaults, custom column collations and known lossy type conversions are rejected.
- Unsupported constraints, unvalidated constraints, external FK targets and
  column-subset `SET NULL`/`SET DEFAULT` actions are rejected.
- Imported expression indexes, INCLUDE columns, custom opclasses/collations,
  unsupported NULL ordering and advanced index options are rejected when their
  semantics cannot be represented. This also applies to indexes owned by constraints.
- CHECK expressions or partial-index predicates with remapped column names are
  rejected when the projection cannot safely rewrite their SQL.

Do not clear warnings or delete preserved metadata simply to make the projection
succeed. Resolve the unsupported feature or manage that schema through a tool
that represents it. Read-only query use of supported imported tables can continue
independently of migration support.

Imported foreign keys do not acquire new indexes implicitly: the importer
projects the indexes present in the catalog. In native declarations,
`foreign_key=True` normally also requests a supporting index; declare
`indexed=False` on the relation when that is not intended.

## Read or export migration recipes

`SqlModelReader` accepts normalized migration data, not a database connection:

```python
from genro_sql import SqlModelReader, SqlPythonEmitter


def recipe_source(normalized_structure):
    builder = SqlModelReader(normalized_structure).to_builder()
    return SqlPythonEmitter(builder).emit(class_name='ImportedDatabase')
```

The returned source is a Python `SqlBuilder` recipe you can save and maintain.
Unsupported structure fields are reported as errors rather than silently
omitted. The migration structure does not contain UI overlays, query formulas
or row-policy configuration; this round trip cannot reconstruct them.

See [Models](models.md) for application declarations and [Importing](importing.md)
for the read-only PostgreSQL catalog API.
