## Phase 1
- Foreman clarification (2026-10-17), confirmed by the user at the gate: `back_reference=` disappears together with `inverse=`; `relation_name=` is the only name of the inverse. The Done grep of the old spellings includes `back_reference`.
- Gate (user, 2026-10-17): `'n::N'` together with `dtype=` raises `dtype passed twice` (the legacy overwrites silently; the grammar raises). The split applies to column, aliasColumn, formulaColumn, subQueryColumn, pyColumn, bagItemColumn, compositeColumn: the legacy routes all of them through `virtual_column`.
- Gate: action values are the legacy full names, any case. SQL: cascade, restrict, no action, setnull/set null, setdefault/set default. Python: cascade, raise, ignore, setnull, optional `:message`. The snake forms set_null/no_action/set_default disappear; abbreviations are Macro 7.
- Gate: `reader.py` (migration JSON -> model) writes `onDelete_sql`/`onUpdate_sql`; the migration JSON keeps `on_delete`/`on_update`. `deferrable`/`initially_deferred` stay (not in the decision).
- Build: compositeColumn does not split `name::dtype`. Its asqueel signature has no dtype: it is a key with dtype JS fixed, like the legacy `dtype='JS'`. bagItemColumn is a semantic element and splits like the other virtual columns.
- Build: a truthy limit/offset that is not a nonnegative int still raises; only falsy values skip the clause.
- Build: `onDelete`/`onUpdate`/`onDelete_sql`/`onUpdate_sql` values are checked by `SqlModelValidator._check_relation`, so every mode (package and physical schemas) refuses a non-legacy name. The x_app_on_delete/x_app_on_update keys are gone: the joiner reads `onDelete`/`onUpdate` directly.
- Build: `onUpdate_sql` absent on a foreign key renders `ON UPDATE CASCADE` in every mode (the renderer applies the default). The reader writes `onUpdate_sql` explicitly (`no action` when the JSON has none) so a database read back round-trips; imported constraints carry both actions as legacy names.
- Build: the automatic `deferred=True` with setnull applies where the package source is resolved (model_source), not in the physical layer: that layer mirrors the database, and an implied deferral would break the reader round-trip.
- Build: `on_duplicate` became `onDuplicate` (decision: relation attributes take legacy names). `FK_ACTION` Literal removed from elements.py; the legacy names map to the JSON actions in `common.SQL_ACTIONS` / `SQL_ACTION_NAMES`.

- Gate: `test_another_named_connection_times_out_without_losing_first_transaction` is rewritten: with a deferred `BEGIN` the other connection reads the committed state instead of failing with `locked`.
- Foreman clarification (2026-10-18): on SQLite a plain read opens no transaction, as legacy (sqlite3 implicit BEGIN only before DML); a deferred `BEGIN` starts at the first write; `for_update` opens `BEGIN IMMEDIATE`, or takes the write reservation when a transaction is open. Source: user decision «transazione SQLite: come legacy (differita; lock solo con for_update)» and the approved proposal of 2026-10-15 «le letture normali non bloccano nessuno». Tests that expect `in_transaction` after a plain SQLite read are realigned; PostgreSQL unchanged.

## Phase 3
- Foreman clarification (2026-10-18), confirmed by the user at the gate. The rule «nessuno deve passare attributi extra» governs what a model author or the legacy loader feeds in, not what asqueel writes for itself.
  1. Keys the option expansion writes (`group_*`, `atc_attachmenttable`, `hierarchical_field_of`, `hierarchical_linked_to`, `one_group`, the `x_legacy_*` of `_legacy()`) are exempt; the expansion output stays unchanged. The exemption cannot be used from outside: the expansion records the keys it generated in the node's `_meta` (as `inherited_attributes`/`type_defaults`) and the validator exempts exactly those; a hand-written one still raises.
  2. No user writes `x_legacy_*`. The loader writes only the four read by name (`x_legacy_order_by`, `x_legacy_draftField`, `x_legacy_logicalDeletionField`, `x_legacy_protectionColumn`); `x_legacy_index_*` has no reader and is dropped. `x_ui_*` is rejected as user input (UI attributes return in legacy spelling in Macro 4): the prefix read in `model.py` goes, `column_ui` builds from configuration overlays only; the loader's `x_ui_*` from type aliases goes too.
  3. `var_*` on formulaColumn is accepted, as on virtualRelation (user decision A3.5).
  4. Legacy grammar read by the core is declared in the signatures: relation `many_order_by`, `eager_one`, `eager_many`, `external_relation`, `resolver_kwargs`, `join_on`; column `trigger_table`. `ignore_tenant` belongs to multi_tenant and raises as a deferred feature.
  5. `from_expanded_legacy_xml` accepts only the keys it maps into the grammar plus its structural keys, and raises naming the first other one. `source.xml` stays byte-identical; the oracle tests strip a copy at load time, with the stripped key list in the test.
- Gate (user, 2026-10-18): a test that uses a free extra only as a carrier moves to a declared attribute (`comment`, `name_short`); a test whose subject is the extra passing through becomes a rejection test.
