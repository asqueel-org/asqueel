## Objective
The migration and the SQLite dialect behave as GenroPy legacy (decisioni.md, Gruppo 7; roadmap Macro 7): SQL action abbreviations, an index on every relation column, `indexed={...}` options, the `foreignKeys`, `force` and `backup` migration options; SQLite schema files named `<schema>.db`, foreign keys switchable per connection, `vacuum()` on every schema, legacy SQL type names. Two proposals for the team close the macro: a capability catalogue and sqlglot transpilation.

## Notes
- Precondition of the run: asqueel-migration 0.3.0 published and installed in `venv/` (`uv pip install -e .[dev,docs]` after the Phase 2 pin, or the release installed before the run). It is built in a separate session in the asqueel-migration repository; the user merges, tags and publishes it. Its scope: (1) `SqliteDatabase.schema_files()` returns `<folder>/<schema>.db`, and the main file's folder is created when missing; (2) the SQLite writer declares the legacy type names (`A` → `character varying`, `C` → `character`, `DH` → `timestamp`, `DHZ` → `timestamp with time zone`, `H` → `time`, `X` → `blob`, the rest unchanged), and the SQLite reader maps both the legacy names and the 0.2 names (`varchar`, `char`, `timestamp without time zone`) back to the same dtype, so databases created with 0.2 show no change. Without it, Phase 2's file-layout and type-name tests stay red.
- Phase 1 does not depend on asqueel-migration 0.3; it runs on 0.2.3 too.
- Run the full suite in the foreground (`--no-cov`; with coverage it exceeds 600 s); a headless executor that backgrounds it ends before the result (Macro 6 lesson).
- Out of this plan, in roadmap `## Debts`: `text_pattern_ops` on `hierarchical_pkey` and column collation (genropy#1708, genropy#1526).
- Decided during planning (2026-10-19): operator classes leave Macro 7 (legacy has none; the prefix-LIKE cost exists only on non-C databases, measured); the SQL index-name rule stays; `vacuum()` covers every attached schema; the SQLite option is named `foreignKeys`, as the migration option.
